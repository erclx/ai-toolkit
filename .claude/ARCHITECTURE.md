# Architecture

Authoring guidance: `standards/architecture.md`.

## Overview

The toolkit is a CLI plus a Claude Code plugin, built so an agent can drive every surface a human can. Content is authored once at a project-root folder, consumed here through a generated copy under `.claude/`, and reaches a target project either by an `aitk` install command or by loading live from the plugin root.

Six domains carry the weight: governance rules, standards, snippets, tooling stacks, plugin skills, and the CLI that installs them. This file holds each cross-domain decision and the alternative it passed over. The mechanism behind one lives in `.claude/context/<domain>.md`, which is where a reader goes for how rather than why.

## Key technical decisions

### Two delivery paths rather than one

`aitk` commands copy governance rules, standards, snippets, and tooling configs into a project, and the marketplace plugin loads skills live from `claude/`. A single channel was the obvious alternative, and neither channel does the other's job. Copied content is what a project edits and owns, so it lands as real files under version control, while a skill is toolkit-owned process that goes stale the moment it is copied.

What the split costs is a citation crossing it, since a skill body naming an installed path resolves only for a project that ran the matching install and an unresolved path raises nothing until a session opens it. A file only one skill reads therefore travels inside that skill, which is what moved the three orchestrator runbooks into `claude/skills/claude-orchestrate/references/`. Publishing on both surfaces was the alternative and it makes two sources for one text.

### A standard travels two routes, neither of which writes into a project

`standards/` reaches a project two ways. The `claude/standards` symlink puts the whole corpus in every plugin cache, and the published package carries the corpus as the CLI's root. The first delivers self-containment to a session and the second to a machine reader, which is why the third route closed: `aitk standards install` wrote the flat root into a target and every copy became a file sync had to reconcile forever. A filed issue measured the cost, where five relocated standards sat 12 to 45 lines behind with no command able to refresh them.

Making the install optional was the alternative and it leaves two populations of targets with different shapes. Breaking is cheap at one known installed target and dearer with every project scaffolded after, so the window was taken rather than migrated, and the one target was repaired by hand. What it costs is that a project holding an old `.claude/standards/` copy resolves nothing through it, since the resolver reads `standards/` at the working root and then the package alone. Measured at `3ac31a09` on 2026-08-20.

A fan-out into each consumer's `references/` was a third route and it is retired rather than standing beside the two above. `standards/bundled/` held six sources copying out eleven times, and growing it to cover the flat corpus was declined on a duplication measurement: the most-cited standard, named by 21 skill bodies across the two catalogs, would have landed a copy in each, scaling the exact duplication the fan-out existed to avoid. That decision reasoned from the install channel closing, on the premise that no bundled standard installed so the fan-out was what carried them, and the premise did not hold: no bundled standard ever installed either, reaching a consumer through its `references/` copy from the start, so closing the install channel took nothing from them and left the real question unasked. What lets the folder dissolve is the fallback citation form thirty-nine bodies already carried, `${CLAUDE_SKILL_DIR}/../../standards/<name>.md`, which serves a root standard to any number of readers at zero copies and inverts the duplication count that argued for keeping the fan-out. The six sources moved to the flat root and the eleven copies came out with them. Measured at `16a80339` on 2026-08-25.

A census over all 27 standards, uniform at the flat root now that the fan-out is gone, bounds the corpus rather than a duplication ceiling with no route left to bound. `.claude/context/standards/destinations.md` carries the per-standard record, the empty drop bucket, and the three destinations withdrawn without being built, one of them a move to the fan-out this decision no longer offers at all. Those three stay in the flat corpus reached by citation. Measured at `bd2be81a` on 2026-08-20, with the withdrawals re-read at `653bbb15` the same day.

A machine-parsed standard is permanently exempt from any design inlining a standard into the rule that cites it, because a rule restating the list a parser reads is two sources for one list. The set is empty, since the three ban sets and the six structural checkpoints that made `markdown.md` and the retired `prose.md` members now ship as data in `src/markdown/`. Relocating a list to a single source the machine owns satisfies that bar rather than breaking it, and the accepted cost is that the prose and the shipped numbers can now drift with nothing comparing them. Measured at `60fc97bf` on 2026-08-19.

A second corpus closed the same channel afterward, on the argument already argued above rather than a new one: tooling stack references. `tooling/<stack>/reference.md` copied into a target as `.claude/tooling/<stack>.md` on `aitk tooling sync`, and every installed copy on this machine had already drifted from source by the time anyone measured it, four lines on one target and twenty-six on the other. `src/tooling/read.ts` resolves a reference the working root ahead of the packaged corpus, mirroring `standardRoots` in `src/standards/read.ts`, and `aitk tooling reference <stack>` is the read verb `aitk tooling sync` stopped writing a copy through. The count this closed at was one target holding one drifted copy, down from the two the row was filed against. Measured at `16591fd2` on 2026-08-27.

### The toolkit consumes its own output

`governance/rules/` authors at the repository root and this repository commits its own consumed copy at `.claude/rules/`, regenerated by `bun run check` and asserted for drift. A citation then spells one path that resolves here and in every target that installed the same content, where reading the authoring root directly would have left each one needing two spellings.

`standards/` was the third member and left, on the argument the two routes above already carry rather than a new one. Nothing installs the corpus into a project, so no reader outside this checkout could ever hold the copy the mirror wrote, and the one spelling it bought was a path only this repository resolved. What it cost to keep was 28 tracked files regenerated on every check and a citation form that read as portable and was not, which is why 40 of the 62 shipped bodies already name the plugin root instead. The three carriers now each cite the root they resolve against, which `internal/rules/claude/598-authoring-layout.md` states as one case apiece. The accepted cost is that a citation here no longer looks the same as the same citation in a rule or a shipped body, so a reader has to know which surface they are on. Measured at `7374bb51` on 2026-08-28.

`snippets/` and `internal/` left together and on two arguments rather than one, which is why neither could be read off the row above. Nothing installs a snippet into a project either, so its mirror bought the same spelling only this checkout resolved while the live `claude/snippets` symlink already served every plugin cache. `internal/` had no install channel to close at all: the mirror existed so a toolkit session could read an internal file at a `.claude/` path like every other consumed copy, and the one standard under it has two readers that both sit at the root beside the source, which is the whole readership. What came out was 15 tracked files and `mirror_dir` itself, leaving `scripts/core/regen-claude-copies.sh` with no mirror call and one delegation to `aitk gov regen`. The accepted cost is a stage still named Consumed copies over a single corpus. Measured at `23e79fbd` on 2026-08-28.

A comparably-shaped external project reached the same mechanism for its own install-and-update path without sharing any code with this one: hash what shipped, compare it three ways against what the project holds and what it last recorded, and skip whatever the project edited. Its version is 779 lines against `src/sync/`'s 5,787, and the convergence matters more than the gap, since two projects reasoning independently landing on one answer is stronger evidence for the mechanism than either project's own reasoning taken alone. Measured at `d5f519ee` on 2026-08-26.

### Location enforces the plugin boundary

Toolkit-internal content lives under `internal/`, a tree nothing inside `claude/` reaches. A filter at each CLI entry point was the alternative, and it is what the repository ran until it failed, because `claude/standards` and `claude/snippets` are symlinks an installer dereferences with nothing left in the path to filter. Five internal files reached every plugin cache that way and the count was growing on its own, so `scripts/core/check-plugin-boundary.sh` now walks the shipped tree with symlinks followed and fails on any file resolving under `internal/`.

A second instance is stronger evidence for the same argument, and it sits in the sync engine rather than the plugin boundary. `locateSource` judges an installed file by name, and relocating five toolkit standards into a subfolder made a sync read them as project-authored with no command able to tell the two apart. A repair pass across three targets found 17 such files, one holding 15 of them under a `project/` subfolder it had already adopted on its own. `SyncAdapter.projectSubdir` answers it the same way, deciding by location before any name lookup runs, and no migration follows: the name inference stays live at the flat root as a floor under new files rather than a replacement. Measured at `5da3214d` on 2026-08-25.

### Three tiers of context rather than one file

Context splits three ways: `CLAUDE.md` and this file load eagerly, `.claude/rules/` load on glob match, and `.claude/context/<domain>.md` is read on demand. One large `CLAUDE.md` was the starting point and grows without bound. Nested `CLAUDE.md` files below the cwd were the other candidate, and they load cheaply but announce nothing, so a session never learns they exist. The `index.md` catalog is what the third tier buys, since it lists every entry up front and a session picks what it needs before touching the domain.

### Three axes decide which tier a fact belongs in

A fact goes to `.claude/rules/` when it fires on a specific path being edited and violating it ships silently, and to a context entry or a skill body otherwise. Recording it in the entry's `## Gotchas` was the alternative, and that is where the manifest-to-reference symmetry sat unread while `#823` shipped a stale reference. Eager loading does not substitute, since a rule delivered at session start competes with the whole file while a glob-matched one arrives attached to the action, which is how `#828` edited without a protocol `CLAUDE.md` carried all session. The test rejects most of what it is run over, because a rule per gotcha rebuilds the `CLAUDE.md` the tiers exist to prevent.

Firing is one axis of three rather than the whole test. The second is conditional presence, which is what a rule buys that a line in `CLAUDE.md` or a seed cannot: a rule loads only for the session whose path matches, where an eager line loads into every session regardless of what is being edited.

The third is updatability, which is what makes `governance/rules/core/` correct as rules for the fifteen of its nineteen rules carrying no `paths:` glob, which load every session anyway since every stack reaches `base` and `base.toml` takes the folder whole. A rule installed through governance sync still carries a later fix to every project that installed it, where a seed line stays fixed at the scaffold it was written into. Measured at 5196cc9a on 2026-08-27.

The test itself is a fact about editing the root file, so it ships as `governance/rules/claude/592-claude-md.md` and arrives attached to that edit in every target that installed governance. Leaving it stated here alone was the alternative and it governs this repository and nothing else, since a target reads its own root file with no copy of this record beside it. A project scaffolding without governance used to be reached by the seed's copy instead. The seed now holds four sections and none of them states the test, so that project is reached by neither surface. A target that did install governance still gets it from two surfaces, this entry and the shipped rule, and nothing compares them.

### Something other than the model resolving a file by path decides whether it installs

A domain installs as a file when something other than the model resolves it by path, and ships as a command when only a session's own judgment would open it. The harness glob-loads a governance rule and expands a snippet the moment an `@` reference fires, and a target's own build tooling reads a tooling config straight off its path, so none of the three needs a command in the loop. A standard is the one domain the model opens on purpose, since nothing else resolves it by name, which is why `aitk standards` carries no install and no sync and its own help says so.

Deciding per domain case by case was the alternative, and it is what actually ran before anyone wrote the criterion down: `src/sync/check.ts` registered snippets and governance once, tooling syncs through a verb of its own, and standards register through neither, four domains landing on one consistent answer that stayed unstated until this row read it back. Snippets retired its own registration afterward, on the same ground standards already had: nothing installs the corpus into a target, so `src/sync/check.ts` now registers governance alone. The criterion held through that change rather than needing a rewrite, since a snippet was already resolved by the harness expanding an `@` reference rather than by the sync engine, and the file registration this paragraph described was a second, now-closed path to the same destination. What it costs is a rule with no verb behind it, since naming the criterion here does not build a check that a fifth domain answers it the same way, and that gap is a decision this row declines to close. A second cost sits beside it: every session pays to read this entry, since `.claude/ARCHITECTURE.md` loads eagerly rather than on demand.

### Skills call the CLI and never reimplement it

A plugin skill reads a catalog through `aitk <domain> list --json`, matches it against project context, then executes the CLI under `AITK_NON_INTERACTIVE=1`. Restating CLI logic in a skill body was the alternative and it puts one behavior in two places that ship on different cadences, so every domain owes a `list` verb with `--json` and no skill hardcodes a rule, stack, or snippet name.

The rule covers a catalog and stops at a document, so a skill reads a standard by path off the `claude/standards` symlink that puts the corpus in every plugin cache, and 38 shipped bodies name that fallback. A rule cannot take that path, being markdown a glob match loads with no skill context, so `${CLAUDE_SKILL_DIR}` expands to nothing and the 18 rules citing a standard name `aitk standards <name>` instead. Describing the plugin corpus in prose was tried first and converts a working citation into a reported failure while reading ambiguously against a project-root `standards/` folder. Measured at `e5abee70` on 2026-08-20.

### TypeScript with a bash exec boundary

`src/` parses arguments and owns every migrated domain, and `scripts/` holds what has not moved, with domains migrating one verb at a time rather than in a single rewrite. Bash keeps only what it is good at. `read_frontmatter_field` stayed because three scripts, two of them list scripts, call it once per field inside a loop, where routing through the CLI would cost a process per read. Coarse operations called once per invocation shell into `aitk` instead.

### Bun as the runtime with no build step

`bin` points at `src/cli.ts` and its `#!/usr/bin/env bun` shebang runs the source directly, so the package ships TypeScript with `tsconfig.json` beside it and nothing compiles. Node with a build step was the alternative, and it costs a publish pipeline plus a `dist/` that can drift from the source a contributor reads. The trade is that the CLI does not run under Node at all, since `Bun.Glob`, `Bun.TOML`, and `Bun.YAML` stand in for globbing and parser dependencies, so a target project needs Bun on the machine rather than only a package manager.

### Hooks enforce what prose only states

A rule written in a standard fires only when a session reads it. The Claude Code hooks in `.claude/hooks/`, the husky hooks, and the drift stages in `bun run check` fire either way, and the scratch-guard hook, the task-board index regen, and the consumed-copy drift assertion each replace an instruction that was already written down and already ignored. The cost is that an enforcement point is code with its own failure modes, so each one has to say what it does when its inputs are missing rather than reporting a pass.

### Content that leaves the repository gates harder than content that stays

The same finding fails a push against `tooling/*/seeds/` and only reports against `.claude/context/`. What moves it is the corpus rather than the measure: a seed is authored once and installed into every scaffolded project, so a defect there propagates, while a context entry is edited by the people who own it and a threshold failing their push teaches them to route around the stage. Widening the `paths` globs on the claude rules was the alternative and it is a nudge, since a rule loads only when a session opens the file. Gating a measure with a known false-positive class forces an escape hatch, so `stub: true` exempts a seed and both install paths strip it before a target sees it.

### A diagram folder per kind rather than one file

`.claude/diagrams/` holds an entry per kind under a fixed filename, chosen over a single `DIAGRAMS.md`. The kinds drift at rates spanning roughly an order of magnitude, so a deploy change rewrites one entry and leaves the others untouched. Fixed filenames are what let a session refreshing a kind find the file it is meant to overwrite instead of writing a second entry beside it under a name of its own. A kind carrying a second question takes a suffixed name and repeats its category, which is how the folder reaches nine entries across five kinds.

### Review travels on the pull request

`claude-pr-review` posts findings as a comment on the pull request rather than returning them to the session that produced them. A finding posted there survives either session ending, which is what an orchestrator and worker pair need when neither outlives the review. `claude-review` still runs locally against the branch diff before a push, so the two compose rather than compete: the local pass catches what it can before the branch leaves the machine, and the pull request holds the durable record.

### Evals measure spec quality rather than efficacy

`scripts/eval/` asks whether a session that has never seen a standard can author a conforming artifact from that standard alone, and says nothing about whether the artifact is useful. No baseline arm and a sample of one are correct for that question, because failure is self-evident: a session that reads the standard and still writes the wrong shape has proved the standard failed to communicate its own central rule. The fixture extracts to `mktemp -d` outside this repository, since a fixture under the root inherits this project's `CLAUDE.md` through the ancestor chain and the session under test would arrive already knowing what the test measures.

### A durable record is named for what it is, not for how long it lives

`groundwork/` and the three archives came out of `.tmp/`, leaving it to hold only what can be deleted without loss. Each is cited by task files months after it was written, so a folder announcing itself as temporary was the wrong container for the one thing in it nobody may delete. `memory-archive/` stayed behind on the same test, since nothing cites a retired memory and it is an undo buffer rather than a record a later session opens.

The memory-review archive is the fourth because a receipt is not uniformly decided. It arrived in `.tmp/` holding 154 receipts and 261 undecided items, which the memory standard calls decision state the next round reads back, so it failed the deletable test on content rather than on citation and reached no records remote while it sat there. What the test reads is whether the judgment behind a file has been taken, and an entry retired by a decision passes it where a proposal nobody answered does not. Measured at `961aa69c` on 2026-08-20.

Prefixing the other five surfaces with a dot to collapse the ignore file into one pattern was measured and declined at 486 occurrences across roughly 150 committed files, 43 of which ship to targets, against 80 across 26 for the move that shipped. It is a breaking rename for every installed target and it hides the board a person opens daily, so the ignore file grows by four entries rather than shrinking. `.tmp` is the only one of the six where hidden is the correct default.

Where each one sits is the second question and it was answered later. A record folder owns its lifecycle subfolders, so an archive is a location inside the record rather than a sibling named after it, and a folder earns root position only when nothing else contains it. The rule shipped with the move rather than after it, because nesting three folders and stating no principle leaves the next surface to earn an archive putting it at the root, which is where the others were. Measured at `106115ba` on 2026-08-21, at 94 occurrences across 37 tracked files, with a further 139 in the gitignored record tree that no `git grep` reaches.

Leaving the pairs as siblings is what the paragraph above reads as settled, and it is not: that measurement is a dot prefix, and nesting appears nowhere in it. The one recorded number that bears on this is the window, since 94 sits between the 486 declined there and the 80 already shipped. What it costs is that two surfaces both named for memory now archive to two places, a retired entry to `.tmp/memory-archive/` and a review receipt to `review/memory/archive/`, which the deletable test separates correctly and nothing else explains.

### The population of consuming projects is recorded as it is created rather than searched for

`putDomain` in `src/sync/stamp.ts` writes each stamped target into a machine-level index beside the sandbox tree, so a project joins the population at the moment a sync installs into it. Sweeping the filesystem was the alternative and it is what the hand census ran, twice, and got wrong in both directions at once: it walked one folder on one machine and reported six consuming projects across eight folders, where two of the eight had never been targets, one was a second clone of a target already counted, and the clone the repair actually ran in sat outside the folder entirely. A walk answers about the paths someone thought to name and a record answers about the installs that happened, and only the second is a fact the toolkit already holds.

The sweep stays as the fallback rather than being retired, because the index only knows an install that ran after it shipped, and it carries the bound with the answer, naming the roots walked, the depth, the folders it stopped at, and the roots it could not read. Two facts a walk has to be told rather than deduce are that a stamped folder can contain other stamped folders, since one repository here holds the eight the census walked, and that a linked worktree carries a copy of its own target's stamp, since one target here has five. Grouping by origin is what makes a target held in two clones count once, and the accepted cost is that nothing removes a row, so a project that was deleted or that dropped the toolkit inflates the count until a read refuses its path. Measured at `427213fc` on 2026-08-30, against eight targets on this machine.

### The durable records back up through a second git directory, not a branch here

`aitk records push` carries the eleven gitignored folders under `.claude/` to a private repository through a second git directory at `.claude/.records.git` with `.claude/` as its work tree, so every path stays where it is. A separate checkout was the alternative and it moves the 275 tracked files that spell one of these paths, which is the whole cost the second git directory exists to avoid. Their size is a per-machine reading rather than a repository fact, since no commit here carries a path under any of them.

An orphan branch on this repository was the cheaper alternative and it is the one this repository cannot take, since it is public and the payload is the memory pen, the review reports, and the groundwork trails. What the split costs is a one-time setup per machine, which both verbs refuse until it exists, and the remote gate that compares the records origin against every remote of this project. Measured at `ca020184` on 2026-08-28, when `.claude/diagrams/` joined the set and took the folder count to eleven. Both numbers count the ten payload folders plus diagrams and exclude `.records.git` itself, which is the mechanism rather than a payload, and the file count reads every tracked file naming one of those paths, which is 275 against the 174 read at `961aa69c` over a narrower pattern.

### A write to shared scratch routes on what it does to the file

Shared session scratch lives at the main worktree root, and a linked worktree is where every worker runs. `Edit` and `Write` refuse a main-root path there and offer the worktree copy instead, so a body naming only the destination reported success and lost the file, which is how two pull requests merged without recording their number on the task they closed. Creating a whole file now goes out as a plain single `Bash` command carrying a heredoc, and changing a line inside a file that already exists goes through an `aitk` verb resolving the root in-process.

Instructing the shell for both was the obvious single rule and it ships the stream editor this repository already bans. Relocating the four folders was the other candidate and it addresses nothing, since the refusal is tool-scoped rather than filesystem-scoped, and it is a breaking rename for every installed target. What the split costs is that two structured edits became code with tests rather than a sentence in a skill body, which is `aitk tasks pull-request` and `aitk tasks outcome`.

### A held skill body is checked against history rather than against itself

A session loads a skill body once and keeps it, so an edit made this session is not picked up, and a compaction carries the held copy forward with the summary. Which shape the staleness takes decides whether anyone notices: a held body naming a file the branch deleted fails loudly, while one naming a file that still exists and says something different resolves and reads current, so the session applies the superseded rule and reports success. That second shape is the ordinary ship shape here, since a branch touching `claude-docs`, `git-stage`, or `git-pr` runs those skills later in the chain that edited them.

`aitk claude skills drift <ref>` names which shipped bodies moved between a ref and `HEAD`, and `standards/session.md` runs it while a session map is written. Comparing the bytes a session holds was the obvious design and cannot be built, because a session has no way to read its own loaded body back, so the substitute reports a file moving rather than a held copy differing. Instructing a session to re-invoke the skill fixes nothing and adding a re-read step to the ship chain is declined on cost, so `governance/rules/claude/570-skill.md` carries the instruction on the body being edited instead. Measured at `34ce48e6` on 2026-08-20.

### A standard governs an artifact's shape and the skill driving it governs the procedure

`standards/teach.md` fixes the layout, the ordinal naming, the frontmatter, and the mission and learning-record formats of a learning workspace, while the pedagogy that decides what to teach next sits in `claude-teach/references/`. An attribute standard beside `markdown.md` was the alternative and it is declined on the second-reader test, since a standard nothing else cites has no owner to correct it. Folding the pedagogy into `standards/teach.md` was the other candidate, and `591-standard-authoring` rules it out, since a standard governs one document type or one attribute rather than both.

The glossary shape moved out of `teach.md` and into a standard of its own beside the pedagogy it was separated from, which carries the same reasoning one step further rather than reversing it. A promoted glossary lands wherever its destination surface puts it, so no glob covers the set and one skill drives every move. It shipped at `standards/bundled/glossary.md`, fanned out into `claude-teach`'s own `references/`, and moved to `standards/glossary.md` once the fan-out that copy depended on retired. The move left both citing surfaces naming a `references/glossary.md` that no longer exists, and only one of them is repaired: `561-teach.md` now reaches the standard through `aitk standards glossary`, which is the form `598-authoring-layout` fixes for a rule, since a rule is read with no skill context. `standards/teach.md` still names the skill's reference in three places and is dead on all three, which nothing detects and `v70.3` is the check for. Measured at `a21cbdf7` on 2026-08-31.

The workspace is also the first record folder named `<nn>-<topic>` rather than by a bare slug, so a listing sorts by when each opened. That was free here because the surface was greenfield, and the 36 folders it named as not free are renamed now on their own row rather than by this decision: 42 groundwork and intake folders share one ordinal sequence across both kinds, derived from the first commit naming a folder where one exists and from filesystem timestamps otherwise, and the CLI's slug resolution widened to match a bare topic against its ordinal-prefixed folder. Measured at `d5f519ee` on 2026-08-26.

### A producer hands off through a file of its own rather than a shared one

`claude-teach` proposes where a durable page belongs and writes each confirmed one to `.claude/.tmp/teach-promotion/<slug>.md`, which `claude-docs` folds and deletes. Sharing `.claude/.tmp/memory-routing/<slug>.md` was the obvious reuse and it is what the pattern cannot take, since that file already has two writers and a reader that deletes it, so a fold triggered by one producer discards whatever the other wrote and never read. A sibling path costs the folding skill one more read and removes the interaction entirely.

The fold reaching the public docs corpus is the cost, since `docs-sync` owns that tree, and the carve-out is landing a page whose destination an operator already confirmed. Splitting the fold across two skills by destination was the alternative and it puts one handoff file under two readers, which is the failure this decision declines in the other direction. Measured at `f0f8bd62` on 2026-08-19.

### A rule the model can talk itself out of moves into a verb

Quiz option order is drawn by `aitk teach lesson` rather than stated in the skill body. The instruction was the cheaper design and it is the one the source this surface departs from already ships, where answers frequently default to the first option while the stated mitigation addresses a formatting leak instead, so porting the instruction ports the defect with the mitigation attached. An author told to vary a position still varies it by judgment, and a verb is a check where an instruction is a hope.

What the split cannot close is that the body remains free to reorder what the verb reports, since nothing downstream compares the two. The sandbox arm records that as a manual entry rather than claiming it, because the order the verb draws is uniform and one run cannot separate a taken order from a chosen one.

### A writing rule travels by whether anything reads it

`standards/prose.md` is retired and its two halves went to different carriers. The bans, the spellings, and the frontmatter wording joined `markdown.md`, which every markdown edit already routes to and which `aitk markdown audit` measures from package data. Voice, rhythm, sentence construction, and information density went to the `write-human` skill, and `500-prose` routes a markdown edit there. One file held both halves and made an enforced rule and an advisory one look identical, so a session was graded on the words it avoided and never on how the prose read.

Keeping a thinner `prose.md` was the alternative and leaves an advisory file under a name that already reached nobody, while folding the bans into the skill puts the enforced list behind a glob-matched pointer and beside the judgment it was separated from. Routing a rule at a skill was declined before as trading a certain load for a probable one, and that objection measures a different chain, since the rule still loads on the glob and names the skill to load. The split cost a 90-file citation sweep and a standard citing a skill, and nothing measures whether output follows the rhythm rules. Measured at `57ee7467` on 2026-08-20.

### A safe behavior sits on the default path rather than behind a flag

`aitk tooling sync` writes nothing until `--write` is passed, and a headless run without it reports and exits 1. The verb already scanned, reported, and prompted, and what made that reporting worthless was `nonInteractiveDefault: true` on the confirm prompt, so `AITK_NON_INTERACTIVE=1` meant apply-all and every scripted sync overwrote the target unasked. ### Color is a question about a destination rather than about the process

### Demo ships to targets, breaking the capture precedent

`aitk demo` ships with the published package rather than staying toolkit-only, so a target installs a browser-driving command for the first time. `aitk capture` set the opposite precedent, staying out of the shipped package because it regenerates images this repository already commits. That reason does not carry to a command whose whole purpose is running inside someone else's project, so the toolkit-only alternative, keeping the driver here and asking an operator to record from this checkout, was declined.

What it costs is a dependency the toolkit itself never carries: `bunx playwright install chromium` before a target's first run, plus the browser binary that command fetches. The toolkit-only alternative avoids that cost outright, at the price of moving the whole feature out of reach of the project it exists to demonstrate. Measured at `6b2c4ca4` on 2026-08-21.

### The dispatch boundary names the property it protects rather than the mechanism

The orchestrator boundary used to read "do not spawn worker sessions with agents," naming a mechanism where it meant to protect independence, being steerable, and a worker's own pull request. A `claude --bg` dispatch is a separate process carrying all three, gated by a collision check composing a worktree listing, the live session roster, and the refs already naming the branch into one `claimed` field (`aitk sessions list --branch`) and by a file-set disjointness test, with a session-name prefix marking a self-dispatch apart from an operator's launch. The Agent tool stays forbidden regardless, since an in-process subagent shares the session's context and cannot be steered or reached independently, which is the property a mechanism-named ban was standing in for all along.

An unconditional dispatch was declined on one data point, one worker shipping a backlog task unattended, and a cap of three concurrent workers bound that path until the operator retired it on 2026-08-27 against seven workers in one afternoon, four concurrent and none colliding. A count knows nothing about what two workers write, so a file-set disjointness test replaced it, at the cost of a bound a dispatcher can talk past, since nothing verifies a serialize reason. The reading count moved from two to three when the first real dispatch produced a branch behind a merged pull request, which neither the listing nor the roster can see. Measured at `83fc7fb5` on 2026-08-27.

### The handoff fires by blocking a compaction, because blocking is the only channel that event has

`.claude/hooks/precompact-handoff.sh` registers on `PreCompact` against the `manual` matcher and refuses the first `/compact` of a session, naming `session-map` in a message the session reads as the blocking reason. Handing the instruction back as `additionalContext` was the design this row planned and the one every other hook here uses, and the vendor reference does not offer it: the field is listed for seven events and `PreCompact` is not among them, exit-0 stdout reaches the debug log for every event but three, and exit-0 stderr is documented as something Claude never sees. Exit 2 blocks compaction and makes the stderr text the blocking reason, which leaves one route rather than a preferred one. Read 2026-08-27 from `https://code.claude.com/docs/en/hooks.md`.

Firing on `auto` was declined by that same finding rather than by the risk this row was parked on. A block is the whole mechanism, and an automatic compaction fires because the window is full, so blocking one strands the session where blocking a typed `/compact` only asks a present operator to answer. The block is bounded to once per session for the same reason, since a hook that refuses every compaction traps the session that wrote a map and the session that declined alike. What it costs is a message whose delivery is documented as a blocking reason and never as text the model reads, so a block landing unexplained is possible and nothing here detects it, though a real manual `/compact` on 2026-08-27 rendered the message in full on this client. The seed copy is withheld because a scaffolded target without the plugin would meet a blocked `/compact` naming a skill it does not carry. Measured at `9960a4d7` on 2026-08-28, with the seven events and the three exit-0 exceptions re-read against the same page and unmoved.

## Risks / open questions

- Skills and the CLI ship at two speeds. A skill merged to `main` reaches a `--plugin-dir` session immediately, while the CLI reaches a user only once a release cuts a tag and the publish job lands it on the registry. A skill calling a verb or flag that has not been published yet fails in a target, and nothing detects that call.
  - The version behind it is now reported. `aitk sync --check` and `aitk claude skills drift` each read the installed version against the newest published one, chosen because they are the two moments a target already stops to reconcile. Neither reports which verb is missing, so a session still meets the absent subcommand rather than a warning naming it, and the reader who never syncs and never checks drift is reached by no route at all.
  - The sandbox is the first place this was observed rather than reasoned about. An arm resolves `aitk` off the machine's PATH, so a `claude:teach` run met a global install carrying no `teach` command at all, refused, and wrote nothing, failing every assertion for a reason the arm is not about.
  - A missing subcommand under a command that exists is the quieter half. Pointing the `claude-docs` plans sweep at `aitk tasks plan-citations` archived neither plan and created no plans archive at all, because the installed binary carried no such subcommand and returned no record to route on. The verb ships and the body keeps stating the rule until a release carries it, a duplication taken deliberately over a sweep that reports a clean pass having done nothing.
  - A path convention crossing the split is the third shape and the loudest of the three. Nesting each archive inside the record it archives put an archived plan under `.claude/plans/`, which an installed binary predating the change reads as live, so `aitk tasks archive` refuses every task whose plan has shipped. The `claude:tasks` `archive` arm failed five of nine assertions on exactly that against a global install at `0.106.0`, while the branch's own CLI archived the task correctly. It fails closed rather than silently, which is the safe direction and still blocks the board until a release lands.
    - The convention side of this closed rather than the release side. `standards/tasks.md` and `standards/plan.md` now state the nested position as a convention a project receives, so the shape a stale binary disagrees with is documented rather than assumed. The failure above turned out to have a quiet counterpart: `aitk tasks archive` on a stale binary does not refuse, it writes successfully to a flat `.claude/task-archive/` sibling, and reached this repository itself on 2026-08-27, caught by a status read rather than by any check, before a hand recovery closed the gap it left open. A `.gitignore` backstop over the two flat spellings was tried and dropped, since it would remove the untracked-status-read signal that caught this instance and contradict `RETIRED_FOLDERS` in `src/records/backup.ts`, which already treats both as paths that moved rather than paths still live.   - `500-prose` and `561-teach` point across the split in the other direction.
