# Standards system

## Overview

Standards are markdown docs that define developer workflow conventions. They install into a target project under `.claude/standards/` and are consumed by AI agents and developers alike. Standards cover workflow conventions, not code style. Code style belongs in governance rules.

## Structure

```plaintext
standards/
├── index.md             ← generated from installed files on install and sync
├── *.md                 ← source standards (authoring happens here)
├── bundled/             ← fan-out sources, not installed to targets, mirrored into skill references
.claude/standards/
└── *.md                 ← committed consumed copy, regenerated by check
scripts/
├── manage-standards.sh  ← entry point (aitk standards)
├── core/regen-claude-copies.sh ← mirrors source into the consumed copy
└── core/regen-skill-references.sh ← fans bundled/ into consuming skills' references
```

`standards/` at the root is the authoring source. The toolkit also consumes its own standards, so `bun run check` regenerates a committed copy under `.claude/standards/` and fails on drift. Rules, skills, and prompts reference `.claude/standards/X.md` so the path resolves identically in the toolkit and in every target install. This mirrors the `governance/rules/` to `.claude/rules/` split.

`index.md` is a generated file. `aitk standards install` and `aitk standards sync` rewrite it under `.claude/standards/` in the target based on which standards are present, reading each file's frontmatter for the link label and description. Do not hand-edit it in a target project.

## Fan-out to skill references

A convention consumed by specific skills rather than authored by a target project lives in `standards/bundled/` instead of the top-level `standards/`. These sources do not install into targets and are not mirrored into `.claude/standards/`. Each carries a `consumers:` frontmatter field listing the skills that read it, and `scripts/core/regen-skill-references.sh` copies it into each `claude/skills/<consumer>/references/`. The consuming skill body loads it with `${CLAUDE_SKILL_DIR}/references/<name>.md`, so the skill works without a target-side `aitk standards install`. The install `find` is `-maxdepth 1` and `regen-claude-copies.sh` excludes `bundled/`, so the fan-out sources never leak into the installed set. `bun run check` runs the fan-out regen and fails on drift, the same guarantee as the consumed copies.

## Authoring a new standard

Follow `.claude/standards/standard.md`. It is the meta-standard: the `title` and `description` frontmatter contract, heading and structure conventions, imperative rule bullets, and when to include examples. It installs into target projects like every other standard, so it governs standards authored in the toolkit and in a target alike. The `prompts/standards-reference.md` generator produces the terse reference style for AI-assisted authoring inside the toolkit.

## CLI

| Command                         | What it does                                                         |
| ------------------------------- | -------------------------------------------------------------------- |
| `aitk standards install [path]` | Copy all standards into a target's `.claude/standards/` (overwrites) |
| `aitk standards sync [path]`    | Update standards already present in target                           |
| `aitk standards list [--json]`  | Emit catalog of standards with descriptions                          |

`aitk standards` with no args shows a picker for `install`, `sync`, or `list`. The install command requires confirmation before writing files.

`--json` emits `{standards: [{name, description, target, content}]}`. Skills that audit drift (`claude-seed-sync`) consume `target` and `content` to diff installed copies part by part. The shape mirrors `aitk claude seeds list --json`.

`aitk standards sync` is file-level. Selecting "Apply all" overwrites whole files and destroys any local customizations. Under `AITK_NON_INTERACTIVE=1`, the command refuses to auto-apply when drifts are detected. For projects that customize sections of `.claude/standards/*.md`, use the `/claude-seed-sync` skill instead. It diffs the preamble plus each `##` section and preserves customizations by default.

## Workflow

To set up a new project:

```bash
aitk standards install ../my-app
# copies all standards into ../my-app/.claude/standards/
```

To sync updates to an existing project:

```bash
aitk standards sync ../my-app
# diffs standards already present, proposes new ones too
```

## Adding a standard

Create a `.md` file in `standards/`. Start the file with a frontmatter block containing `title` and `description` (see `.claude/standards/prose.md`). Run `bun run check` to regenerate the consumed copy under `.claude/standards/` and commit it. Run `aitk standards install` to push to a new project or `aitk standards sync` to update an existing one.

## Notes

- Standards are the same across every project, no stack variation, no extends chain.
- `aitk standards install` overwrites all standards intentionally.
- `aitk standards sync` only updates files already present, never adds new ones.
